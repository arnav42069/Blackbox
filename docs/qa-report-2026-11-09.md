# BlackBox QA report — 2026-11-09

The final QA workflow passed on the repaired application: **104 Python tests, 12 browser tests, frontend typecheck/build, and real Ollama probes**. The controller recorded **119 passing result entries, zero failures, zero skips**, exit 0, in 42.99 seconds. These entries include two frontend commands and one grouped model result; they are not 119 independent test cases. Additional installed-launcher and shutdown checks passed.

The implementation is [scripts/qa_loop.py](../scripts/qa_loop.py), with the executable wrapper [scripts/qa-loop.sh](../scripts/qa-loop.sh). The existing instructions are [docs/qa-workflow.md](qa-workflow.md). Run from the repository root:

```bash
./scripts/qa-loop.sh --report-only
```

The wrapper executes the repository's `.venv/bin/python scripts/qa_loop.py`, forwarding all arguments. The exact command used for both the baseline and final full runs was:

```bash
./scripts/qa-loop.sh --report-only --model huihui_ai/qwen3.5-abliterated:4b --budget-seconds 300
```

This mode freezes source into `.runtime/qa-runs/<run-id>`, links the installed dependencies, and builds/tests that copy. The final run used `http://127.0.0.1:8765`. It used synthetic sessions and temporary data/config directories, normal pairing, mocked Ollama protocol responses, and real localhost HTTP/SFTP fixtures. Nmap and ping exercised only a loopback fixture. Out-of-scope addresses were denial assertions; no external lab was contacted. The real model session received no target scope and executed exactly one successful `host.preflight` call, with zero tool HTTP requests. No dependencies or models were downloaded.

The initial report-only launch exited 2 because another QA process already held the writer lease. That run was left alone; this audit's full runs started after it released the lease. This was an infrastructure precondition, not an application test failure.

The unchanged baseline full run passed 96 Python tests and all frontend/browser/model checks. Additional malformed-response tests then exposed **eight failures**: null, array, string and numeric `message` values raised `AttributeError` at `.get()` before the ordinary response repair or completion-review repair could run. [The fix in `core/agent.py`](../backend/blackbox/core/agent.py) validates message/call/function object shapes and parses calls before reading content. Malformed values now enter the existing bounded `ValueError` handling. Four cases verify successful recovery and actual host execution; four verify two invalid completion reviews end in the intended explicit failure. An expected failed agent session in these negative tests is a passing test assertion, not a QA failure. All eight focused cases passed after the fix and again in the full run. No existing test expectation or execution permission was weakened.

A second defect appeared during artifact verification: browser tests passed, but their promised `browser-tool-journal.json` was absent. Uvicorn 0.38.0 re-raises captured SIGTERM after lifespan shutdown, so the fixture's export and cleanup after `uvicorn.run()` could never execute. The shutdown verifier gained a journal-presence assertion; it failed before the fix despite successful port cleanup (exit 1 from the verifier). The fixture now exports its read-only database journal and cleans its pairing files and temporary directory inside a wrapper around the application lifespan, after the original lifespan closes the database. Both shutdown methods passed the strengthened verifier after this fix. The final full browser run retained 6 tool records and 139 events. Existing application tests also passed again.
